## 2. Core Concepts & Taxonomy

### Controlled Task Taxonomy
Every task generated by the engine belongs to a strictly defined taxonomy:

1. **`EXTRACT_RESPONSIBILITY`**: Isolate AST responsibility signals into dedicated domain components.
2. **`SEPARATE_BUSINESS_RULE`**: Decouple extracted Phase 4 business rules (validation, threshold, calculation).
3. **`EXTRACT_CALCULATION`**: Isolate financial derivations and mathematical formulas.
4. **`ISOLATE_PERSISTENCE`**: Isolate database mutations and entity manager operations.
5. **`ISOLATE_STATE_TRANSITION`**: Isolate domain lifecycle transitions (e.g. `PENDING` -> `COMPLETED`).
6. **`ISOLATE_EXTERNAL_NOTIFICATION`**: Isolate asynchronous event publishing or notification dispatch.
7. **`DEFINE_INTERFACE`**: Define clean contract interfaces for extracted modules.
8. **`INTRODUCE_ADAPTER`**: Provide protocol or interface mapping between legacy and modern.
9. **`INTRODUCE_FACADE`**: Wrap legacy component to preserve caller compatibility.
10. **`REDUCE_DEPENDENCY`**: Decouple unnecessary direct dependencies.
11. **`SPLIT_COMPONENT`**: Decompose class into modular domain helpers.
12. **`MIGRATE_CALLER`**: Update direct dependents identified in Phase 5 impact analysis.
13. **`PRESERVE_BEHAVIOR`**: Enforce explicit invariant preservation for rules.
14. **`ADD_VERIFICATION_CHECKPOINT`**: Attach verifiable assertion criteria to major refactoring milestones.

## 3. Data Flow & Traceability Matrix

Every generated task maintains end-to-end evidence links:

```
Modernization Task 
  ──> Responsibility Signal (Source File & Line)
  ──> Business Rule ID (Condition Expression & Formula)
  ──> Impact Surface Entity (Caller Component Name)
  ──> Modernization Strategy Recommendation (MODULARIZE)
  ──> Verification Checkpoint Assertion Criteria
```

---

## 4. Verification Checkpoint Contract

Verification checkpoints are deterministically attached to plan milestones:

- **Rule Representation**: Asserts that legacy condition expression (e.g. `amount > 50000`) is preserved in extracted module.
- **State Invariant**: Asserts that previous -> new state transitions (e.g. `PENDING` -> `COMPLETED`) remain intact.
- **Caller Interface Equivalence**: Asserts that direct callers (`AccountController`) receive expected return structures.
- **Persistence Boundary**: Asserts that database state mutations retain expected entity schema contracts.
